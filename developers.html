✦ For developers ✦

RAMen inside your app.

Give your app's local AI a memory: every conversation comes back in seconds instead of being read again, and long ones stay fast. On computers your app talks to RAMen like any model server. On Android and iPhone, the RAMen kit goes inside your app.

On a computer or a server

Start RAMen (ramen start) and point your app at it. It answers the APIs apps already speak, so there is no new client to learn:

  • OpenAI: http://127.0.0.1:8090/v1 (chat completions and Responses)
  • Anthropic Messages: http://127.0.0.1:8090
  • Ollama: ramen start --ollama replace answers at Ollama's own address, with your Ollama models

Send the whole conversation each time, as usual. To name a conversation yourself, add an X-Session-Id header. On a shared GPU server (the Server plan), give each person a key with ramen keys add NAME and start it with ramen start --api-keys ~/.context-engine/api-keys.txt --host 0.0.0.0.

On Android: the RAMen kit

1. In settings.gradle.kts, inside dependencyResolutionManagement { repositories { ... } }:

exclusiveContent {
    forRepository { maven { url = uri("https://getramenai.com/maven") } }
    filter { includeGroup("com.getramenai") }
}

2. In app/build.gradle.kts (minSdk 29):

implementation("com.getramenai:ramen:0.9.0")

3. Hello world:

val ramen = Ramen.open(context, File(context.filesDir, "Qwen3-1.7B-Q4_K_M.gguf"))
ramen.reply(listOf(Message.user("Name three kinds of noodles.")), session = "chat-1") { r ->
    when (r) {
        is Reply.Text -> answer.append(r.text)
        is Reply.Done -> Log.i("app", "read ${r.readTokens} new tokens, memory: ${r.memory}")
        is Reply.Failed -> Log.e("app", r.message)
        is Reply.Started -> {}
    }
}

Send the whole conversation each time (system, user and assistant messages), as with the OpenAI API, and RAMen reads only what is new. history(session) returns a conversation's saved messages, forget(session) deletes it, and close() frees the model's memory. Answers arrive on the main thread. The kit runs any GGUF model your app ships or downloads, needs no permissions, and works on arm64 phones and x86_64 emulators. Tested in a blank app with only these two snippets: the conversation came back after Android closed the app, and the model read only the new message. This is a 0.9.0 preview.

On iPhone: the RAMen Swift package

1. In Xcode: File > Add Package Dependencies, enter https://github.com/MatthewLeibel/ramen-swift, choose version 0.9.0 and add the RAMen library to your app. Or in Package.swift:

.package(url: "https://github.com/MatthewLeibel/ramen-swift", from: "0.9.0")

2. Hello world:

import RAMen

let ramen = try Ramen.open(model: modelURL)   // a GGUF file your app ships or downloads
let chat: [Ramen.Message] = [.user("Name three kinds of noodles.")]
for try await reply in ramen.reply(chat, session: "chat-1") {
    switch reply {
    case .text(let text, _): answer += text
    case .done(let done): print("read \(done.readTokens) new tokens, memory: \(done.memory)")
    case .started: break
    }
}

The same rules as on Android: send the whole conversation each time and RAMen reads only what is new. answer(_:session:) returns only the finished answer, history(session:) a conversation's saved messages, forget(session:) deletes it, and close() frees the model's memory. iOS 16.4 or newer; on a phone, an A13 chip or newer (iPhone 11 and later); the simulator works on Apple silicon and Intel Macs. Tested in a blank app with only this snippet: the conversation came back from its memory file after the app ended, and the model read only the new message. This is a 0.9.0 preview; before you ship it in an App Store app, write to support@getramenai.com.
